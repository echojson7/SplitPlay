# Research 9 (round 2, "max-out"): input, audio, game-compatibility isolation
[V] verified against source/local code, [U] unverified (lab). Local code read: OpenStreamMS, Duo wiki, Vibepollo 4afd9da, libvirtualgamepad, moonlight-common-c 5d3c0ec, Sunshine d7e5fe0.

## Top findings
1. **Surround without patching rdpendp:** a remote protocol provider can supply its own per-session audio endpoint enumerator: service asks QueryProperty(WTS_QUERY_AUDIOENUM_DLL); DLL exports GetTSAudioEndpointEnumeratorForSession(SessionId, IMMDeviceEnumerator**), implements IAudioOutputEndpointRT / IAudioInputEndpointRT; stack falls back to stock interfaces otherwise; DLL "must be signed so that secure processes can load it" [V MS docs]. Fits the rdpcorets-wrapping provider already planned.
2. **Full DualSense with haptics precedent:** Vibepollo (GPL-3) builds composite DualSense (HID + 4-ch USB Audio) via loopback USB/IP server + usbip-win2 UDE driver, forwards haptic PCM [V dualsense_usbip_gamepad.cpp]; PCM uses LI_CCAP_HAPTICS_PCM only in Nonary's moonlight-common-c fork. Upstream has rumble, trigger rumble, LED, motion, touchpad, battery, adaptive triggers, no PCM haptics [V]. libvirtualgamepad docs: true DualSense haptics need USB audio function, impossible with VHF/UHID [V].
3. **RDP USB redirection (RemoteFX/RDPEUSB) is per-session isolated:** "one user cannot use a device that has been redirected in another session" [V Win7-era docs] → session-scoped virtual USB devices on in-box drivers, fed by the seat client, no server-side signed driver [U Win11 client + loopback].

## Ranked ideas
1. **KB/mouse through the loopback RDP connection** — gain high, cost ~2–3 pw. Worker → shared-memory ring → seat sends FreeRDP fast-path PDUs (scancodes, Unicode, pointer, wheel/hwheel, X1/X2); relative mouse TS_FP_RELPOINTER_EVENT (MS-RDPBCGR) [V]; FreeRDP 3.0 added relative mouse [V]. Gains: input from session's own RDP devices → Raw Input real hDevice, no LLMHF_INJECTED [U]; UAC/lock screen/Ctrl+Alt+Del work without SYSTEM desktop switching/SendSAS [U]; network-facing worker no longer injects. Main risk: whether 26100+ server advertises relative mouse in input capability set [U] — fallback: keys/buttons/wheel via RDP, relative motion via SendInput. Split wheel >~255; pass keyboard layout (Duo v1.5.3). Latency <1 ms expected [U, LDAT]. Unmodified Moonlight OK. Touch/pen via RDPEI (FreeRDP rdpei) instead of InjectSyntheticPointerInput [U pen server side].
2. **Own per-session audio endpoint via provider's audio enumerator** — gain very high, cost ~4–6 pw. 7.1/5.1/stereo 48 kHz float per session (matches Moonlight 2/6/8 ch [V Limelight.h]) + own mic endpoint; capture straight into shared memory for worker (no WASAPI loopback, no rdpsnd dependency, no PCM to seat, no host-speaker leak). Risks: DLL loaded by shared audio stack (audiosrv/audiodg) — a bug kills audio in all sessions incl. console → tiny, lock-free; audiodg signing level [U] (Duo #382 hit signature mitigations); whether a wrapping provider can return own enumerator on client SKUs (NonRDPPatch) [U]. Bridge: stereo Remote Audio, event-driven capture, 5 ms Opus packets (Sunshine LAN default [V rtsp.cpp]); OpenStreamMS measured ~70 ms loopback-to-seat-output with 10 ms buffers [V docs/puestos-locales.md].
3. **Mic via RDP audio-input channel** — FreeRDP audin custom backend + audiocapturemode:i:1, ~1 pw. Upstream Moonlight has no mic [V]; optional for mic-capable forks.
4. **Harden VHF pads** — libvirtualgamepad (MIT): Xbox Series via xinputhid, DS4, DualSense (adaptive triggers, LEDs, motion, touchpad), Switch Pro [V]. Remove stamping race: one source devnode per desktop via SwDeviceCreate with DEVPKEY_Device_SessionId at creation; pre-register HidHide session-jail entries (HID\…!N) for predictable child IDs; backstop CM_Register_Notification + one devnode restart if late (OpenStreamMS GamepadSessionIsolation.cs) [V]; VHF children inherit SessionId? [U]. Disable ControllerToVKMapping [V]. DS4 default profile (Duo v1.5.9) [V]; Xbox Series only when needed (4-slot XInput pool [V]). Map rumble, trigger rumble, LED, adaptive triggers, motion to Moonlight callbacks.
5. **Haptics PCM → rumble envelope** for unmodified Moonlight (band-split to low/high motors); PCM direct to Nonary-fork clients.
6. **Virtual USB devices via RDP USB redirection from seat client** — gain high, cost ~6–10 pw, risk high. FreeRDP urbdrc backend emulating devices; tsusbhub attaches only to session N; in-box drivers: xusb22 (genuine X360, impossible via VHF), hidusb, usbaudio (composite DualSense with haptics + mic). Pads session-only without stamping/HidHide; no driver to sign; could carry UAC2 7.1 speaker as fallback to #2. Risks: RemoteFX USB redirection on Win11 Pro over loopback [U]; interrupt/isoch latency [U]; Duo "XInput driver focus" limitation [V exists]. Alternative precedent: usbip-win2 (Vibepollo, GPL-3, author-signed, separate install) + SessionId.
7. **Per-title compatibility shims (opt-in allow-list, never on anti-cheat titles)** — hide remote session (SM_REMOTESESSION, WTSClientProtocolType, SESSIONNAME, console comparisons), DXGI exclusive fullscreen → borderless (Duo docs DXVK/Borderless Gaming [V]), launcher Global\ → Local\. Precedents: OpenStreamMS SteamHook patches steam.exe IAT to localize Global\Valve_SteamIPC_Class and move SteamPID/TempAppCmdLine HKLM→HKCU [V steamhook.c]; Duo AppCompat-database "process patching": hide remote session, isolate Bluetooth pads, Steam isolation, XInput focus fix, "verifier opt-out for anticheat users" [V].
8. **Per-process XInput slot virtualization** hook — only when >4 XInput-profile pads total.
9. **Clipboard/files** — clipboard already per session (own WinSta0); keep cliprdr, rdpdr, drives, printers, USB (except #6), camera, smartcard off on loopback; Moonlight has no clipboard/file channel (Apollo needs matching clients [V]); optional HTTPS upload page per desktop with PIN, written under user's token with MotW and size limits.

## Rejected
Per-session virtual HID KB/mouse (Windows doesn't route HID KB/mouse into remote sessions; OpenStreamMS switched to WinUSB + inject [V]; libvirtualhid SAL); patching rdpendp (signature mitigations, global, update breakage); global virtual audio sinks (not visible in RDP sessions — Dante FAQ [V title]; leak path); process loopback for surround (apps mix to endpoint format = stereo; launcher trees missed); ViGEm/XUSB bus emulation (EOL, no session isolation); InputInjector gamepad (restricted capability; Duo moved away); GPU-PV VM per desktop as default (Duo "Sandbox"; anti-cheat, RAM; future tier).

## Game compatibility [U, lab matrix]
No exclusive fullscreen/VRR [V Duo] → borderless/shim. Store/Game Pass (GDK/MSIXVC, Gaming Services) in non-console sessions untested; own account/licence per desktop. Steam needs hook + own account (one game at a time per account). Epic, EA app (system service shared across sessions), Ubisoft, Riot single-instance unknown. Anti-cheat (EAC, BattlEye, Vanguard, FACEIT) in remote sessions unknown; triggers: remote flag, injected input (#1 removes), shims, DLL in TermService.
