# Research 10 (round 2, "max-out"): GPU resources, multi-GPU, performance isolation, system tuning
(unv) = unverified, (est) = estimate.

## Bottom line
On one shared GPU "no mutual influence" cannot be guaranteed: WDDM time-slices each engine between processes [S1]; consumer Windows has no spatial partitioning and no per-process VRAM limit. Only one GPU per heavy desktop gives hard isolation (3D time, VRAM, NVENC, TDR). On a shared GPU target bounded interference: (1) top GPU priority for the small streaming path (DWM compose, IDD copy, CSC, NVENC submit); (2) cap each desktop's game at the stream fps; (3) admission control from measured per-session cost.

## Ranked ideas
1. **Top GPU priority for the encode path.** Worker already does as Sunshine: D3DKMTSetProcessSchedulingPriorityClass (REALTIME, or HIGH on NVIDIA with HAGS) + IDXGIDevice::SetGPUThreadPriority(7) (display_base.cpp). Better: copy/CSC on a D3D12 compute queue with D3D12_COMMAND_QUEUE_PRIORITY_GLOBAL_REALTIME (succeeds or fails, never silently downgrades; "guaranteed to execute before any other queue"; needs privilege — worker is SYSTEM — and driver preemption) [S2]. Same priority for IDD WUDFHost; DwmEnableMMCSS(TRUE) per session (unv). Gain (est): stream path 0.1–0.3 ms GPU/frame; without priority several ms of jitter behind game command buffers; with priority ≈ preemption latency (sub-ms, unv). Main lever for p99 at 250–500 Hz. Cost: days. Risk: NVIDIA freezes with REALTIME+HAGS+VRAM near full [S3] → HIGH default, REALTIME opt-in while VRAM headroom >~15%.
2. **Cap each desktop's game at the stream fps.** (a) VSync back-pressure via IDD mode: no exclusive fullscreen in remote sessions → games present through session DWM; if DWM composes at the IDD mode per session, VSync-on games are capped with no injection; at 250–500 Hz the VSync penalty is 2–4 ms (unv — lab test). (b) NVIDIA DRS "Max Frame Rate" per exe via NVAPI (Sunshine already writes DRS: nvprefs/driver_settings.cpp); machine-wide per exe, applies at process start. (c) Opt-in injected RTSS-style limiter (anti-cheat risk). Gain (est): a game at 300 fps for a 120 Hz stream wastes ~60% of its GPU time. Largest throughput/isolation lever on a shared GPU.
3. **One GPU per heavy desktop.** IDD calls IddCxAdapterSetRenderAdapter(LUID) before monitor arrival (a preference; OS may choose another, e.g. adapter PnP-stopped [S4]) → service verifies actual adapter and alerts. Games steered per user (each desktop = own user): HKCU\Software\Microsoft\DirectX\UserGpuPreferences\<exe> = "SpecificAdapter=<id>;GpuPreference=<n>;" [S5]; per-user default DirectXUserGlobalSettings "HighPerfAdapter=VEN&DEV&SUBSYS;" [S6]; choosing between two dGPUs needs Win11 build 25336+ [S7]; service writes into HKU\<SID> or loaded NTUSER.DAT. Encode on the same GPU's NVENC. Evidence: 58/60 games honour per-app preference, 2 UE4 titles ignore it [S5]. Whether HKCU prefs apply in remote sessions and whether DXGI adapter 0 = IDD render adapter (unv, lab test). Gain: removes 3D/VRAM/NVENC contention; TDR per adapter. Cost: hardware, PCIe x8/x8 ~1–3% (est). Risk: game on GPU X, DWM on GPU Y → cross-adapter copy via system memory (no GeForce P2P on Windows, unv): 8.3 MB/frame 1080p, ~0.4 ms, ~4 GB/s at 500 fps (est).
4. **iGPU tier for light desktops** (render+compose+encode on Intel QSV / AMD VCN iGPU; 60–144 Hz browser/video/indie). Zero dGPU load; bypasses GeForce 12-session NVENC cap. Risk: iGPU often disabled in BIOS; Intel/AMD >1080p240 unmeasured. Rejected variant: NVIDIA render + iGPU encode at 500 Hz.
5. **CPU partitioning & power policy per session.** One job per desktop session (jobs can't span sessions); assign explorer/launchers early. Hard affinity or SetProcessDefaultCpuSets (CPU Sets soft; restrictive affinity wins; exclusive reservation OS-only [S8]). AMD dual-CCD X3D: one desktop per CCD; disable PPM/3D V-Cache optimizer parking in multi-desktop mode [S9]. Intel hybrid: P-cores split between games; worker/DWM on E-cores or one reserved P-core (unv). Opt out of EcoQoS & timer-resolution throttling via SetProcessInformation(ProcessPowerThrottling) — Win11 no longer guarantees timer resolution to occluded/windowless processes [S10]; use CREATE_WAITABLE_TIMER_HIGH_RESOLUTION. High-performance plan, core parking off, ASPM off; NVIDIA PREFERRED_PSTATE max for worker (Sunshine: disabling "can lead to significantly increased encoding latency" [S3]). NIC RSS/interrupt affinity off game cores (~11–16k pps per desktop). Gain (est): lower frame-time variance; X3D V-cache CCD +10–25% (unv). Risk: games self-pinning, anti-cheat vs affinity (unv), Steam breakaway from job.
6. **Admission control & telemetry in UI.** PDH GPU Engine(*)\Utilization Percentage (pid_X_luid_Y_phys_0_eng_N_engtype_3D/Copy/VideoEncode) (unv names), GPU Process Memory\Dedicated Usage, GPU Adapter Memory, D3DKMTQueryStatistics; pid→session via ProcessIdToSessionId; PresentMon (ETW, MIT) in session 0 sees all sessions; worker encode metrics; NVML encoder utilization/sessions (WDDM GeForce support unv). Model (est): Σ(game GPU-ms × cap + compose + CSC) ≤ 85% adapter time; Σ VRAM ≤ 85–90%; NVENC 1080p-eq fps budget; <12 sessions on GeForce. Closed-loop governor lowers the offender's cap/priority (priority live; DRS not live). No per-process VRAM limit on consumer WDDM — overcommit stutters everyone; admission is the only defence; VRAM headroom also gates REALTIME.
7. **TDR blast radius & recovery.** Defaults [S11]: TdrDelay 2 s, TdrLimitCount 5 in TdrLimitTime 60 s → bugcheck, TdrDdiDelay 5 s → 0x116. Keep TdrDelay; opt-in raise TdrLimitCount so one crash-looping game can't bugcheck the host (MS labels keys dev-only). Multi-GPU: TDR resets only that adapter (whether other sessions' DWM hold devices on all adapters unv). Recovery: worker handles DXGI_ERROR_DEVICE_REMOVED, re-opens adapter by LUID, re-checks render adapter, resets NVENC; service watches events 4101/141 and restarts only affected workers.
8. **HAGS on** (DLSS FG on console needs it), HIGH GPU priority by default; lab-measure class strictness with/without HAGS.
9. **"No limits" hardware tier.** RTX PRO Blackwell (pro driver): no NVENC session cap; RTX PRO 6000 Blackwell 4 NVENC + 4 NVDEC. MIG +gfx (GB20X): 4× 1g.24gb+gfx with own NVENC/NVDEC/SMs/VRAM [S12] — likely vGPU-VM only (unv), different product. Workstation platforms with x16 per GPU.

## Rejected
NVFBC (deprecated Win10+, last build 17134 [S13], can't capture remote IDDs); NVENC session-cap driver patch (EULA, breaks on updates); NVENC engine pinning (no API; driver load-balances); per-process VRAM/GPU hard limits (unavailable); job CPU rate-control hard caps / DFSS (stalls, unv on client); REALTIME CPU class for worker (use HIGH + MMCSS); Hyper-V GPU-P per desktop (still time-sliced, anti-cheat hates VMs); lowering TdrDelay / disabling HAGS; GlobalTimerResolutionRequests (unv, unnecessary).
