# Уроки из changelog Duo (v1.0.0 – v1.5.9)

Источник: https://github.com/DuoStream/Duo/releases (все 6 страниц). Ниже то, что относится к SplitPlay, с решением, куда это идёт. «Уже в плане» значит, что это уже есть в docs/ARCHITECTURE.md или в коде скелета.

## 1. Главный вывод: Windows Update ломает всё, что лежит рядом с RDP

Duo раз за разом выпускал исправления под конкретные обновления:
- KB5030310 (23H2 preview) сломал масштабирование;
- поддержку 26100.7523+ пришлось добавлять отдельно;
- HDR перестал работать на 26100.6584+;
- KB5065426 перевёл буферы swapchain на D3D12;
- KB5079473 принёс новый драйвер дисплея RDP;
- KB5083769 вызвал проблемы с правами;
- KB5089573 принёс новый terminal server.

В v1.2.0 им пришлось переделывать патчи RdpIdd/IddCx, «чтобы обновления больше их не ломали». В v1.3.5 они отключали Memory Integrity, чтобы патчить эти DLL, и только в v1.4.6 добавили её поддержку.

**Что делаем:**
- Своя IDD вместо патчей RdpIdd/IddCx остаётся в плане (этап 4). Она не требует отключать Memory Integrity.
- **Новое (этап 3/5):** еженедельный прогон на свежих сборках Windows (Insider Release Preview / последний накопительный пакет) на лабораторной машине, плюс матрица «сборка Windows → проверено» в документации.
- **Новое (этап 4, IDD):** кольцо захвата должно принимать буферы swapchain, которые IddCx отдаёт как D3D12-ресурс (после KB5065426), а не только D3D11.
- **Новое (этап 3):** TermWrap и всё, что трогает termsrv, проверяется по версии `termsrv.dll`. На незнакомой версии служба не падает, а переводит стол в Faulted с понятной ошибкой.

## 2. Сессии и учётные записи (этап 3)

- **Новое:** номер порта RDP-Tcp брать из реестра (`HKLM\SYSTEM\CurrentControlSet\Control\Terminal Server\WinStations\RDP-Tcp\PortNumber`), а не считать, что это 3389. В v1.5.9 у Duo столы не стартовали при нестандартном порту.
- **Новое:** паролям учёток столов ставить «срок действия не ограничен» (`UF_DONT_EXPIRE_PASSWD`). В v1.4.9 у Duo пароли истекали.
- **Новое:** проверить и протестировать:
  - имена пользователей с пробелами (v1.0.6);
  - пароли со спецсимволами (v1.5.1);
  - кнопку «Проверить учётные данные» в настройках стола (v1.5.3).
- **Новое:** учётка без пароля (v1.5.4). RDP её не пускает, поэтому служба сама ставит случайный пароль и хранит его зашифрованным. Пользователь пароль не видит.
- **Новое, важно для тебя:** раскладка клавиатуры в столе по умолчанию берётся из раскладок пользователя хоста, а не en-US (v1.5.3, v1.5.6). Иначе в столе не будет русской раскладки.
- NLA всегда включён (v1.3.2). Уже в плане: seat подключается с NLA.
- WTS API иногда зависает. Duo вынес вызовы WTS в отдельные подпроцессы (v1.2.1). **Новое:** все вызовы WTS в службе делать с таймаутом в отдельном потоке, а зависший стол переводить в Recovering.
- Перепутанные кадры, когда новая сессия получала номер не по порядку (v1.5.1). У нас кольцо захвата привязано к id стола через `ATTACH_DESK`, а не к номеру сессии. Это уже в плане; добавить тест на такой случай.
- Столы приостанавливаются, когда хост уходит в сон (v1.4.4). **Новое (этап 3):** обрабатывать `PBT_APMSUSPEND`/`RESUMEAUTOMATIC`, после пробуждения пересоздавать сессии.
- Windows Home без прав администратора у пользователей (v1.4.5). Учтём в тестовой матрице.
- BluetoothUserService в сессиях столов уже заведён (issue #3). **Новое:** не падать на системах без Bluetooth (у Duo это ломалось на Windows Server, v1.5.5).

## 3. Частота кадров и захват

- Виртуальный монитор залипал на 30 Гц (v1.5.5), был отдельный ограничитель на 30 Гц (v1.5.3). Это стандартный лимит RDP. У нас уже в плане `DWMFRAMEINTERVAL`; добавить автотест, что сессия реально отдаёт больше 30 кадров/с.
- Баг «терялся каждый 500-й кадр» (v1.5.5). **Новое:** в трассировке кадров (`trace.h`) считать пропуски по `frame_id` и выводить их в метрики.
- Тиринг из-за драйвера дисплея (v1.2.5, v1.5.1) и снижение CPU простаивающего IDD (v1.5.3). Уже в плане: захват по событию и заборы (fences), без опроса.
- Курсор: анимированный, монохромный, размеры и смешивание (v1.1.1). **Новое (этап 3):** тесты на все три типа курсора (цветной, монохромный, маскированный) в композиции курсора.
- Режим, разрешение, частота, масштаб и HDR задаются из Moonlight (v1.2.9). Уже в плане.
- Масштаб 100–500 %, суперсэмплинг 100–500 %, «Force SDR», белый SDR, параметры HDR автоматически. Уже в требованиях.
- Видеокарта для стола: по умолчанию та, где больше выделенной видеопамяти, плюс выбор вручную для каждого стола (v1.3.2, v1.5.6). У нас `gpu: auto` уже есть; **новое:** правило выбора для auto — больше всего VRAM.
- Опция «перезапускать GPU при выключении» от зависаний монитора (v1.5.3) относится к их режиму VM. Запомним на будущее.
- DirectX 8/9 приложения (v1.5.5). **Новое:** добавить игру на D3D9 в лабораторные тесты этапа 3.

## 4. Игры, которые не хотят работать в удалённой сессии (самый большой продуктовый риск)

Duo добавил «process patching» через Application Compatibility API (v1.5.5, по умолчанию выключено с v1.5.7). Он нужен для:
- приложений, которые отказываются работать в удалённой сессии (`SM_REMOTESESSION`);
- ограничения фокуса XInput: геймпад отдаётся только активному окну консоли;
- HID-изоляции Bluetooth-геймпадов.

Для античитов есть отдельный выключатель, иначе они срабатывают. Steam тоже пришлось изолировать (мультибоксинг, Steamworks SDK).

**Что делаем:**
- **Новое (этап 3, исследование):** набор из 10–15 популярных игр (включая Steam-игры и одну с античитом) прогнать в столе и записать, что работает. Это покажет, нужен ли нам свой «патчинг процессов».
- **Новое (этап 4):** если нужен, делать его через официальные shim'ы Application Compatibility (как Duo после v1.5.7) и только по выбору для конкретного приложения, с предупреждением про античиты.
- **Новое (этап 4):** Steam в нескольких столах одновременно, отдельная задача.
- Режим «песочницы» Duo (Windows Sandbox / VM с GPU-PV) — это обход для игр, которые не идут в RDP-сессии. Отметим как идею для этапа 5+, не раньше.

## 5. Геймпады (этап 4)

- Duo ушёл от ViGEmBus сначала к своему UMDF-драйверу DualSense Edge (v1.5.8), потом сделал DS4 по умолчанию, «потому что работает в большем числе игр» (v1.5.9). Наш SplitPlayPad (DS4 поверх VHF) совпадает с их итогом. **Новое:** DualSense и Xbox (через GameInput, кнопки Elite видны только так) добавить вторым и третьим профилем.
- Microsoft выпустила API синтетических контроллеров, которым Duo заменил ViGEmBus (v1.5.7). **Новое:** исследовать его как запасной путь без своего драйвера.
- **Новое:** отключать `ControllerToVKMapping` (Windows превращает геймпад в нажатия клавиш, и изоляция ломается) и возвращать как было при остановке службы (v1.5.1, v1.5.5).
- HID-изоляция ломалась при смене консольной сессии (v1.5.4). **Новое:** обрабатывать `WTS_CONSOLE_CONNECT`/`DISCONNECT` и быструю смену пользователей.
- Перенаправление PnP-устройств вместо HidHide и сторожевой процесс для физических HID (v1.2.1). Учтём при реализации изоляции.

## 6. Установщик, служба, эксплуатация

- **Подписанные сборки (v1.5.8).** Для нас критично: драйверы IDD и Pad для обычных пользователей нужно подписывать через Microsoft (attestation signing, нужен EV-сертификат). **Новое:** отдельная задача и решение о сертификате до этапа 4. Без него драйверы ставятся только в тестовом режиме Windows.
- Правило брандмауэра размножалось при переустановке (v1.5.4), после удаления оставались файлы (v1.5.4, v1.5.7). У нас установщик сначала удаляет правило, и CI проверяет удаление. Уже в плане.
- Исключения антивируса ускоряли запуск (v1.4.4). **Новое:** при установке предлагать добавить папку SplitPlay в исключения Defender (по желанию).
- Перезапуск службы из веб-интерфейса и из самого стола (v1.5.5). **Новое (этап 3):** кнопка в веб-интерфейсе и приложение «SplitPlay: перезапуск» в списке приложений Moonlight.
- Логи с идентификаторами событий и настраиваемой подробностью (v1.5.7); лог Sunshine по умолчанию «none» ради скорости (v1.5.3). **Новое:** уровень лога воркера по умолчанию `warning`, настраивается в веб-интерфейсе.
- Защита от двойного запуска менеджера (v1.5.3) и падения от частых кликов (v1.5.3). У нас трей и веб работают через API службы; добавить защиту от повторных команд старт/стоп (идемпотентность уже есть).
- Автозапуск приложений для каждого стола (v1.5.3) и свой список приложений для каждого стола (v1.2.8). Добавить в этап 3/4.
